# Введение в C# и платформу .NET

Лабораторные работы по задаче «Мастер прогулов 80-го уровня».

## Лабораторная 1 — консольное приложение

Программа моделирует один семестр из 100 дней, по шесть пар в день:
матанализ, линейная алгебра, дискретная математика, программирование, физика,
английский язык. Используется одна стратегия студента — обучение по наблюдениям.

### Запуск на Windows

Требуется **.NET SDK 10**. Из корневой папки репозитория в PowerShell:

```powershell
dotnet run --project src/Lab01
```

Для повторяемого эксперимента можно задать начальное значение генератора:

```powershell
dotnet run --project src/Lab01 -- --seed 42
```

Без `--seed` начальное значение выбирается автоматически и печатается в консоли.
Одинаковое значение воспроизводит семестр при той же версии .NET и программы.
Приложение выводит результат семестра, общее удовольствие и среднее за **100**
дней. При отчислении оба показателя удовольствия равны нулю.

Пример для `--seed 42` на .NET 10.0.12:

```text
Семестр завершён: 100 дней.
Общее удовольствие за семестр: 560
Среднее удовольствие в день: 5,60
```

В Visual Studio с поддержкой .NET 10 можно открыть `SharpLabs.sln` и выбрать
`Lab01` запускаемым проектом.

### Правила моделирования

- В начале семестра каждый преподаватель независимо получает одно из трёх
  правил. Поскольку распределение в условии не задано, типы равновероятны.
- Для правила 2 предмет A выбирается равномерно из шести предметов.
  Для правила 3 A и Б выбираются равномерно без повторений. Собственный предмет
  преподавателя тоже может быть выбран. Правила сохраняются весь семестр.
- Третье правило — исключающее ИЛИ (XOR): вчера спросили ровно по одному из A и Б.
- Перед первым днём все шесть результатов «вчера» равны `false`.
- Все опросы текущего дня зависят только от предыдущего дня. Результат опроса
  определяется и для пропущенной пары.
- Успешный прогул даёт 1 очко. Пирожок даёт 1 очко в конце каждого дня,
  который студент завершил без отчисления.
- Если на пропущенной паре спросили, семестр для студента прекращается,
  всё накопленное удовольствие обнуляется, дальнейшие очки не начисляются.
- Предполагается, что студент узнаёт результаты опросов по всем шести предметам
  завершённого дня. На успешном прогуле результат тоже известен: его не спросили.

### Как студент принимает решения

Стратегия **не получает преподавателей, их правила, случайные числа или результаты
ещё не посещённых пар**. Она получает только историю опросов и верхнюю оценку
доступного удовольствия. Наблюдения добавляются после завершения дня.

Для каждого предмета студент рассматривает 22 гипотезы:

| Гипотеза | Количество | Начальный вес каждой |
| --- | ---: | ---: |
| Случайный опрос с вероятностью 50% | 1 | 1/3 |
| Повторить вчерашний результат предмета A | 6 | 1/18 |
| XOR вчерашних результатов A и Б | 15 | 1/45 |

Для XOR порядок A и Б не влияет на результат, поэтому достаточно 15 неупорядоченных
пар. Суммарный начальный вес каждого типа правил равен 1/3.

После наблюдения несовместимые детерминированные гипотезы получают нулевой вес,
вес случайной гипотезы умножается на 0,5. Затем веса нормируются до суммы 1.
Это обновление вероятностей по формуле Байеса. Вчерашние результаты и текущие
веса позволяют оценить вероятность `p` того, что сегодня спросят.

Перед каждой парой вычисляется:

```text
M = накопленное удовольствие
    + число оставшихся пар (включая текущую)
    + число оставшихся пирожков (включая сегодняшний)
```

Это верхняя оценка конечного удовольствия при успешном прогуле. В случае успеха
прогул добавляет 1 очко, а неудача лишает накопленных и будущих очков. Осторожная
оценка выгоды: `(1 − p) × 1 − p × (M − 1) = 1 − p × M`.
Студент прогуливает, только если **`p × M < 1`**, иначе идёт на пару.
На первом дне он посещает все пары. По мере накопления наблюдений он начинает
пропускать занятия с малой оценочной вероятностью опроса.

Это эвристика для увеличения ожидаемого удовольствия, а не доказанная оптимальная
стратегия. Случайного преподавателя нельзя исключить по конечной истории,
поэтому вероятность отчисления остаётся ненулевой. Гарантировать отсутствие
отчисления можно, посещая все пары; тогда удовольствие равно 100.
Теоретический максимум за семестр — 700 (600 прогулов и 100 пирожков).

### Проверка

```powershell
dotnet build SharpLabs.sln --configuration Release
dotnet run --project tests/Lab01.Tests --configuration Release
```

Проверки запускаются отдельным консольным проектом без сторонних NuGet-пакетов;
при ошибке процесс возвращает ненулевой код. Проверяются правила опросов,
вчерашние результаты, начисление и сброс удовольствия, обучение стратегии,
воспроизводимость и границы результата на серии семестров.

Проверено на Windows, SDK 10.0.401 / .NET 10.0.12: сборка без предупреждений,
15 проверок успешны. Для значений seed от 0 до 999 среднее итоговое удовольствие
равно 345,59, отчислений — 6 из 1000. Эта статистика описывает только данный
эксперимент и не гарантирует результат следующих запусков.

### Структура

- `src/Lab01/Program.cs` — параметры запуска и вывод.
- `src/Lab01/Teacher.cs` — скрытые правила преподавателей.
- `src/Lab01/Semester.cs` — порядок событий и подсчёт результата.
- `src/Lab01/IStudentStrategy.cs` — данные, доступные стратегии.
- `src/Lab01/BayesianStrategy.cs` — обучение по наблюдениям и выбор прогулов.
- `tests/Lab01.Tests/Program.cs` — автоматические проверки.
